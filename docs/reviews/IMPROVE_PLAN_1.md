## 작업 순서와 설계

### T1. 문서 메뉴 경로 분리
- 업무 문서 화면을 `/docs`에서 `/papers`로 옮긴다(목록, 상세, 확인). FastAPI 기본 문서 경로(Swagger, ReDoc, openapi.json)는 끈다.
- 모든 메뉴 화면 테스트를 상태 코드가 아니라 **화면 제목과 핵심 내용**으로 검사하도록 바꾼다. 수정 전 코드에서 실패하는 회귀 테스트를 먼저 둔다.

### T2. 실제 AI 흐름: AI 출력 → 사람 확인 → 후속 업무 변화
- 문서 접수 시 키가 있으면 실제 Claude 호출로 구조화한다. 화면과 이력에 추출 주체(AI 모델 또는 대체 추출), 소요 시간, 인용 검증 결과(통과 수, 근거 없음 수)를 남긴다.
- 담당자 확인 화면에서 AI 제안 항목을 채택, 수정, 기각할 수 있고, **AI 제안과 사람 확정의 차이**를 이력에 남긴다. 확인된 내용만 후속 처리(소명 확인 → 재상신 가능, 정정 확인 → 마스터 새 버전 → 재판정)로 이어진다.
- AI 호출에 시간 제한을 두고, 실패하면 대체 추출로 떨어지며 사유를 표시한다. 화면에 AI 연결 상태(키 등록 여부)를 표시한다.
- 실제 호출 검증은 사용자가 키를 등록한 뒤 배포본에서 한다(T5).

### T3. 방문자별 작업 공간 (실험 격리)
- 문제: 누구나 초기화, 시나리오 실행, 승인을 누르면 다른 방문자(심사위원)의 화면이 바뀐다. 검토자도 "시작부터 37건이 승인돼 있던" 상태를 봤다.
- 설계: **견본 공간 + 방문자별 작업 공간.** 시작 시 초기 상태의 견본 공간을 하나 만든다(누구도 바꿀 수 없음). 방문자는 처음에 견본을 읽기만 하고, **처음 상태를 바꾸는 순간** 자기 작업 공간이 견본에서 복제된다. 이후 그 방문자의 모든 조회와 변경, 초기화, 시나리오 실행은 자기 공간에만 적용된다. GET만 하는 방문과 헬스 체크는 공간을 만들지 않는다.
- 구현: Postgres는 작업 공간마다 스키마, SQLite는 작업 공간마다 파일. 작업 공간 ID는 쿠키. 오래 쓰지 않은 공간은 정리하고 개수 상한을 둔다.
- 전역 스위치 제거: 재검증 해제와 입금계좌 대조 끄기는 설정이 아니라 **계산으로만** 대조 화면에 보여준다(대조 B, D). 안전 장치를 끄는 버튼을 없앤다.
- 화면에 "내 작업 공간(다른 방문자와 분리됨)"을 표시하고, 역할 쿠키는 인증이 아니라 시연용 전환이라고 적는다.

### T4. 핵심 사건과 다음 행동 우선 표시
- 대기열 맨 위에 **조치가 필요한 사건**을 먼저 보인다: 막힌 이유, 다음 담당자(역할), 다음 행동.
- 사건 상세 맨 위에 요약 카드(합계, 경로, 지금 막힌 이유, 다음 행동과 그 버튼), 긴 근거와 JSON은 접어 둔다.
- 현재 역할이 할 수 있는 일이 없으면 어느 역할로 바꿔야 하는지 안내한다.

- 은행 회신 검증: 성공과 반려 외의 값은 거부하고 상태를 바꾸지 않는다.
- 격리 DB에서 병렬 요청 시험과 재시작 시험을 테스트로 남긴다.
